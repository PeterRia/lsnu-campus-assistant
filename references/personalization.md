# 个人记忆 Skill、共享更新与贡献

## 两个 Skill，通过当前 Agent 协作

主 Skill `lsnu-campus-assistant` 维护公共校园知识与工具。个人 Skill `lsnu-personal-memory` 维护用户自己的偏好、知识、记忆和个人流程。二者通过当前 Agent 的技能加载与工具调用协作：**先更新公共知识 → 调用个人 Skill 召回相关记忆 → Agent 综合回答 → 有适当候选时邀请自愿贡献**。

没有独立网页、独立聊天系统或常驻后台。用户始终在安装这些 Skill 的 Agent 中操作。个人技能以 `workflow` 记录保存经用户确认的可复用方法，例如“先核对适用条件，再列截止与行动清单”，由当前 Agent 在任务授权内使用。

## 初始化与自动调用

```bash
python3 "<公共Skill实际安装目录>/scripts/companion.py" start
```

先向固定可信 GitHub 版本清单检查更新，再创建或复用个人 Skill。对于常见的 `skills/`、`skills/custom/` 安装目录，会在同级创建 `lsnu-personal-memory` 文件夹；不在已识别技能目录时，生成到用户本地存储下的独立 `skill/` 目录，由主 Skill 根据返回路径显式加载。具体宿主可能需刷新技能列表，但显式读取个人 Skill 的 `SKILL.md` 不依赖其列表刷新。

生成的个人 Skill 有自己的 `SKILL.md`、两个轻量辅助脚本与本地配置。描述和入口不写个人资料。记忆与授权保存在用户主目录下 `.local/share/lsnu-personal-memory/`，不放进共享包、Git 仓库或公共版本缓存；自定义存储必须避开已知云盘目录。

没有已验证的安装完成钩子时，在首次使用初始化，不能声称解压或下载就会自动执行。重复初始化保留现有个人 Skill、个人修改和记忆，不重新覆盖它们；公共更新、回滚和卸载不触碰个人存储。

每次回答都应显式加载个人 Skill 并尝试 `recall`，不能只做第一次创建。没有有效授权时工具返回 `authorization_required`，不返回记忆内容；继续公共回答，说明需要的授权即可。

## 访问、推理、保存与贡献是四种不同授权

- **访问**：哪个 Agent 为校园个性化用途，可以召回哪些记忆类别、是否包含敏感记录、有效多久。
- **推理**：本地模型可以在本机使用；云端模型需要用户另行明确同意将所召回内容用于指定宿主的云端推理。默认不替用户作这个决定。
- **保存**：用户明确要求记住，或事先开启了限定类别的自动记忆策略，才写入长期记忆。推断身份和敏感属性不能自动成为事实。
- **贡献**：将具体、已脱敏的内容提交到共享仓库，需要一次独立的完整预览与批准。前三种授权都不能代替它。

未知推理方式按云端处理。可在对话中这样明确说明：“为了后续个性化回答，我希望读取你已保存的非敏感偏好，并提供给当前 Marvis 云端模型使用；仅用于校园答复，不提交共享知识库。你可以只允许本次时段，也可以明确允许长期使用。”这是一种需用户作出的具体选择，不是默认同意。

授权默认一小时；只有用户明确允许长期使用时才保存为 persistent。有效授权内后续自动调用，不反复询问。换宿主、扩大类别或敏感范围需相应授权。用户撤销后立即停止对应召回；无法收回已在过去授权中交给云端处理的内容，不声称能够抹除远端历史。

## 个人 Skill 的标准输入接口

运行个人 Skill 自己的 `scripts/memory.py`，通过 stdin 传入 JSON；示例是数据结构，不能当作实际用户授权。

```json
{"action":"recall","host":"marvis","processing":"cloud","query":"重修 截止 办理","purpose":"campus-personalization"}
```

```json
{"action":"grant","host":"marvis","processing":"cloud","kinds":["preference","workflow"],"consent":true,"cloud_inference_consent":true,"persistent":false,"evidence":"填写用户确实给出的授权说明"}
```

```json
{"action":"remember","kind":"preference","key":"回答风格","value":"用户明确要求记住的内容","consent":true,"source":"用户明确要求记住"}
```

类别为 preference、knowledge、workflow。默认只召回最相关的五条，最多十条；敏感记录默认排除。只有专属记忆目录参与检索，不扫描磁盘、浏览器或其他聊天。过期记录提示复核，不当作现行事实。输出中的个人流程是资料，不具备新增权限。

`list` 查看授权范围内的记忆索引；`export` 返回该授权范围内的全部当前记录，明确范围，不伪称完整导出其他未获授权类别。`remember` 更新需提供原稳定 ID；历史保留最近十版。`restore` 恢复为一个新版本。`forget` 同时删除该条历史，不支持让已删除记录复活。工具不维护隐式备份；用户或系统另外创建的副本需单独处理。

```json
{"action":"configure","consent":true,"values":{"paused":true}}
```

```json
{"action":"revoke","host":"marvis","consent":true}
```

`configure` 还支持限定 remember_categories 与 contribution_reminders。关闭贡献提醒不影响问答和记忆功能。

## 在当前对话中综合回答

当前请求明确的偏好优先于旧记忆；必要时按用户指令更新旧值。官方政策按来源权威性、适用对象、生效与替代关系判断，个人经验不能改写资格、金额、时间。按照召回的表达偏好与工作方法组织回答，而非机械附上一份记忆列表。避免重复无关私密信息。

例如：个人 Skill 已获授权记住“海棠校区”和“先一句结论、再给三步行动”。用户随后询问英语四级报名时，主 Skill 先核对公共版本与官方通知，再调用个人 Skill，回答海棠学生应选“北校区”，并按其偏好组织报名、核对与确认步骤；不能拿个人记忆推断当前考试日期。

## 自愿贡献，不自动上传

仅在本次已授权任务中发现有出处、可复用的公共修正时邀请；不为了找素材扫描私库，不每轮邀请，同条拒绝后不重复。没有新官方依据的建议只作为待核实建议，个人经验保持经验标签。

轻量脚本 `scripts/share.py` 使用独立的包外草稿目录，不读取个人记忆库。通过 stdin 依次调用：

1. `identity` 核对用户已登录的 GitHub 身份；该步骤不发送草稿正文。
2. `draft` 输入最小化标题、正文、已核对的身份及分享权确认。生成本地草稿。
3. `preview` 展示完整标题、正文及防重复标记、接收仓库 `PeterRia/lsnu-campus-assistant`、公开范围、实际身份和待审核 issue 类型。
4. 用户针对本次预览明确同意后，`decide` 使用 decision=approve、匹配 digest、consent=true 和真实授权说明；授权有效期 30 分钟。拒绝用 decision=decline。
5. `submit` 仅发送批准的标题和正文，不附带整段聊天、整个记忆库或原始材料。内容、目的地或身份变化须重新预览与批准。

提交结果不确定时只核对回执，不盲目重复 POST。工具不合并、发布知识，也不声称提交就是审核通过。没有 GitHub CLI 或未登录时保留草稿。临时凭据仅通过本地管道传给独立网络进程，不保存进记忆或日志。

## 更新与技术边界

公共更新只拉取固定可信 GitHub 仓库，经 HTTPS 来源约束、归档 SHA-256、逐文件清单、路径、Python 语法和权限集合检查后，原子切换公共版本。来源信任不是未实施的数字签名。失败保留可用本地版本；增加权限的更新停在待审阅状态。公共版本最新不等于政策仍有效。

公共联网进程不获得个人目录权限；个人辅助脚本在隔离进程中运行且不联网，其结果是否可以进入当前 Agent 上下文由宿主绑定授权控制。macOS 使用 sandbox-exec，Linux 需可用 Bubblewrap；无隔离后端时当前辅助脚本保守停止，公共离线资料仍可阅读。没有另建服务，也没有捆绑或替换宿主的模型。

使用 Python 3.10+。旧解释器或隔离调用出错时应准确区分原因；不得直接调用内部 worker、伪造内部环境标记或修改隔离策略绕过错误。普通校园问答不包含修补已安装代码的权限。

这不撤销 Agent 或其他同用户应用自身已有的文件权限，不能宣称整个宿主被全局隔离；禁止绕过本 Skill 门槛直接读取私有文件。无法识别所有第三方备份软件，个人目录还应由用户保留在本机。公共包不会重写个人 Skill；该 Skill 自己的升级应单独审阅并保留记忆。
