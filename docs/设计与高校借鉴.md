# 乐师校园助手：十校实测、源码拆解与迁移设计

研究日期：2026-09-22—23；实现版本：1.0.0。

这份记录回答三个问题：其他学校真正怎样工作，哪些做法值得学，哪些已落到乐师版。比较的是本次 Marvis 会话与当时可读实现，**不是学校排名，也不是全面性能评测**。学校的具体制度仍须本校当前官方文件证明。

## 1. 研究方法与证据范围

逐个在 Marvis 技能广场使用参考 Skill，以虚构学生情境实际发起对话，读取最终回答；交大增加一轮回答与追问。检查安装包的 `SKILL.md`、关联知识、参考模块和关键脚本，再追溯可确认的公共仓库。

北大与交大的首次测试保留了部分案例默认提问，可能影响任务范围；下文将这一点纳入解释。其余测试使用明确的独立测试题。复旦另开独立对话复测，以确认结果属于指定 Skill。未使用个人账号、真实成绩或家庭材料。原始私人会话、其他学校知识库和原始学校 PDF 不进入本仓库。

证据分为三类：

- **实测观察**：在 Marvis 最终回答中实际出现的内容，不代表其中每项学校政策都已由本项目独立核实。
- **源码发现**：从安装包或固定提交读取到的规则和算法，不等于功能已成功运行。
- **本项目实现**：本仓库可读代码、工作流和已执行验证；验证结论另见 [验证报告](验证报告.md)。

### 具体值得警惕的失误

这些是本次有限测试观察，不能归因于某一文件的唯一因果；宿主模型、默认提示、工具状态都会影响答案。

1. **引用格式漂亮不等于引用可信。** 华农答复出现含 `327xxx` 的链接；广大引用主要是本地路径。乐师引用落到官方 URL，并要求实际读过。
2. **“审校过”不是有效性证明。** 中南财源码的审校表将国家奖学金 8000、励志 5000 视为稳定；本项目核对到乐师 2026 原通知分别是 10000、6000。不能跨校套金额，更不能只信自审标签。
3. **检索年份不是制度有效期。** 公共套件的 `--year` 主要筛文档年份；不能据此断言该年仍有效。乐师分别存 `published_on`、`verified_on`、明确适用期，未知为 `null`。
4. **时间表需要计算。** 北大回答里“10:10 到场、步行 10 分钟、准备 15 分钟”对应应在 09:45 出发，但后文写成 09:55。乐师通过脚本校验冲突，模型据返回值解释；不让叙述代替算术。
5. **先读资料再判缺口。** 广美对 OCR 缺失的坦诚值得学；“查不到”和“系统坏了”、“有标题未读附件”是不同状态。
6. **陪练只指出已经成立的问题。** 交大追问很具体，但曾直接说两组数据不匹配，原回答其实未说明是否匹配。乐师反馈应说“如果不是同一批，会……；请说明匹配设计”。

## 3. 从源码看到的四种架构

### 证据检索型：华工／广大／深大／华农／广美

主链路：Markdown 原文与元数据 → 分词及同义词 → SQLite FTS5／BM25 → 命中片段 → 回读完整文件 → 按条件、流程和证据回答。

这类 Skill 的价值来自可追溯资料和决策规则，不是换一段学校介绍。它们共享不少工程结构，但语料覆盖和增强材料不同。广美增强版还区分官方、已收录的社交经验与在线补充。

乐师采用同样的“先找、再读、再回答”思路，但当前只有 19 张精选证据卡，没必要引入分词库和持久索引。独立实现中文二元词片段与关键词扩展、BM25、精确主题加权，查到后仍需回读。检索分数只表示相关性。

### 个人事务型：北大与南大

北大将时间固定事项、截止、弹性事务、地点和个人偏好分开。南大从参与记录生成周报，不将预约等同于完成。两者都把个人状态放在 Skill 外。

乐师复用了这一数据设计思想，独立写了日程和成长统计工具。JSON 由助手从自然语言整理，普通用户不必学习数据格式。工具默认输出，不主动建立个人档案。跨校区时间缺证据时标为未知；运动时长缺失时列出缺口。

### 多任务入口型：交大与复旦

交大把入口写短，分模块处理学习、日程、答辩等事情。复旦包含较多课程／培养方案／评价／日程脚本，说明深功能最终需要数据接口、账户状态与计算工具支撑。

乐师把短入口、按需参考、确定性计算组合起来。试讲是本校师范场景的核心扩展，但不是套一个“扮演老师”人设：需要目标、对象、任务、反馈与再练的循环。实时余座、个人成绩与预约接口不因提示词出现就被宣称已支持。

### 离线手册型：中南财

单文件便于下载、搜索与交接；但内容逐年增加后，同一手册里会混杂永久、学期与实时信息。

乐师使用可读的 Markdown 入口与分主题卡片，兼顾离线阅读和逐条维护。每卡有来源、日期、适用对象、短引和限制，更新一项不必重写整本手册。

## 5. 乐师版的具体构成

```text
SKILL.md                 识别任务、证据规则、路由与行动边界
references/              按需加载的办事、日程、学业、陪练、成长工作流
kb/catalog.json          来源、发布日期、核查日、适用对象与校验信息
kb/cards/*.md            19 张可独立阅读的官方事实卡
scripts/campus.py        检索、回读入口、公开原页变化检查
scripts/planner.py       周次展开、重叠、交通、弹性方案、ICS
scripts/credits.py       课程去重、明确认定、学分缺口
scripts/progress.py      完成记录与周统计
scripts/maintain.py      完整性、文档链接、发布包校验清单
tests/                   可执行的行为验证
examples/                明确标注的虚构数据
docs/                    使用、研究与真实验证记录
```

知识来自乐师官方，重点覆盖海棠／苏稽、2026 秋季考试与重修、奖助、图书馆、新生、校历和办事入口。已获得并视觉核对 2026—2027 校历 PDF；验证码保护且未取得的制度附件只列入口，不填猜测条款。

### 与乐师场景的对应

- **一校两区**：区分实际校区和旧业务系统标签；四六级报名的“北校区”按当期通知映射海棠，不能凭名字增加第三校区。
- **师范培养**：试讲、说课、普通话文本练习、实习复盘；正式等级和资格只认官方标准。也支持非师范专业的答辩与面试。
- **多培养类型**：普通、公费、专升本、研究生不能共用一套资助、转专业或毕业条件。
- **办事时间**：学生申请、学院报送、考试与缴费分别处理，日期级通知不补造 23:59。
- **新馆启用**：旧借阅规则与新馆阶段开放公告联读；可自习不等于能借还。

## 6. 以后怎样继续学与迭代

先选一个高频问题，再选一个异常情境。例如重修报名配“已报名但未缴费”，日程配“固定课套住两个短活动”，资助配“学院截止尚未到但学生截止已过”。用同样的问题在参考 Skill 与乐师版各试一次。

记录四件事：用到了什么材料、调用了哪个工具、用户最后能做什么、哪里还缺证据。回到源码定位：问题来自缺知识、路由、检索、计算，还是表达。只补相应一层，不用加长全局提示词掩盖数据缺口。

下一批优先取得当前作息、完整转专业／学位／三字一话条款、校车、真实办事位置与专业培养方案。每补一项，要同时更新来源卡、适用范围、一个用户场景和必要的行为测试。个人系统接口应另立集成工作，以官方页面、正规登录和真实回执验收。

具体安装与日常使用见 [使用文档](使用文档.md)，维护步骤见 [贡献指南](../CONTRIBUTING.md)。
